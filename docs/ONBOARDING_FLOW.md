# 시작 테스트와 프로필 흐름

사용자 요청: 소개 → 아바타 → 6분야 테스트 → 육각형 그래프·강점/보완점 → 메인.
이번 기능은 기존 main-screen 브랜치에 의존한다. 기반 기능과 함께 검토하며 main은 직접 수정하지 않는다.

## 책임과 데이터

- `OnboardingPanel`: 입력 수집, 단계 이동, 선택 상태, 서비스 데이터 표시. 채점은 하지 않는다.
- `ProfileService`: 검증과 실행 중 프로필 생성. UUID는 서비스에서 한 번 생성한다.
- `StarterAssessmentService`: 로컬 시작 테스트 전용 출제·제시 단계·입력 식별·판정·응답시간.
- `QuestionView`: 정답·해설 없음. 기억 제시 중에는 보기 없음. 3초 후 자극 문자열도 제거.
- `AssessmentResult`: 6개 분야별 정답 수·문항 수와 정답률. 미완료 조회 거부, 불변 목록.
- `RadarChart`: 전달받은 6개 정답률 표시. 미측정은 다각형을 채우지 않음.
- `HomePanel`: 같은 프로필·결과를 받아 아바타·그래프와 6개 분야 선택 표시.

## 시작용 계약 (정식 측정 계약과 구분)

1. 분야 순서: 수학, 논리추론, 공간지각, 기억, 주의집중, 사고전환.
2. 고정된 간이 객관식 3문항씩 제공한다. 기존 전체 미니게임의 축소 프리뷰이며 학년별 표준화 문제가 아니다.
3. 3초 기억 제시 외에 응답 제한시간·보너스·난이도 자동 조절·보상은 도입하지 않는다.
4. 시각은 단조 시계로 읽고 응답시간은 밀리초로 보관한다. 기억 제시 시간은 응답시간에서 제외한다.
5. 현재 문항 ID와 보기 범위를 검증한다. 이전 문항 재제출·제시 중 제출·완료 후 제출을 거부한다.
6. 그래프는 분야별 정답률이다. 별도 환산 점수로 저장하거나 IQ로 해석하지 않는다.
7. 2/3 이상 맞힌 분야는 이번 과제의 강점으로 격려, 나머지는 연습 문구를 보여준다.
   이는 시작 UI의 임시 피드백 기준이다. 분야 간 단순 점수 순위로 추천하거나 인지 취약을 확정하지 않는다.
8. 성별은 선택하지 않아도 된다. 프로필은 출제·점수·추천에 사용하지 않는다.
9. 결과 확인 전 메인 이동 버튼을 제공하지 않는다. 모든 테스트 완료 뒤 사용자가 메인으로 이동한다.
10. 저장소 연동은 하지 않았으며 프로필·답안·결과는 종료 시 사라진다. 완료 통계나 저장 성공으로 위장하지 않는다.

정식 백엔드에는 아직 이 흐름의 서비스 계약이 없으므로 별도의 `brainclassroom.onboarding`에 격리했다.
기존 PracticeService를 인지 측정으로 호출하거나 기존 공통 enum·파일 저장·보상 로직을 복사하지 않았다.
추후 정식 서비스의 화면용 데이터·단계·오류·기록 계약에 맞춰 이 시작 서비스를 교체한다.
프로필 나이·성별·아바타 저장 형식과 최초 실행 여부 저장도 백엔드 담당자와 확인해야 한다.

## 검증

`bash scripts/check.sh`: 서비스 경계·모든 정오답·타이밍·중복 요청·기록 불변성과 실제 Swing 입력 순서를 검증한다.
가상 프로필로 선택·응답하여 서로 다른 분야 정답률을 만들고, 결과와 메인의 그래프 값이 같음을 확인한다.
실제 데스크톱 창 수동 검증과 headless 화면 렌더링은 별개다.
